# 0.2.1 待发送引用记录与块标记清理

## 问题

Bridge 在引用被 DSH 领取后保存 `claimed` 记录，但旧的 discard 路径只删除该记录，不处理捕获时
自动写入笔记的 `^dsh-note-*` 块标记。同时，插件在 DSH 真正领取前就显示“已引用到 DSH”，后台
Web Viewer 暂停时会造成已经成功的错觉。

## 修改

- 新引用持久保存块 ID 所有权：`plugin-created` 或 `pre-existing`。
- 现有 v2 记录在启动校验时回填所有权；`dsh-note-*` 识别为插件生成，其他块 ID 视为已有块。
- DSH discard 到达时，先幂等清理插件拥有的未共享标记，再删除 Bridge pending 记录。
- 同一块仍被其他 pending 引用或任何已发送回链使用时保留标记；笔记或标记已经不存在也视为清理完成。
- 选择后显示“引用已提交，等待 DSH 接收”，claim 持久化成功后显示“引用已加入 DSH 会话”；两者均为非阻塞 Notice。

## 验证

- `pnpm check`
- 13 个测试文件、59 项测试全部通过。
- 新增覆盖：编辑/阅读模式所有权、旧记录回填、安全删除、重复 discard、共享 pending 与回链保护。

## 数据边界

该版本不会删除用户原有块 ID，也不会删除已经发送的注释或反向链接。历史孤儿记录需要在部署后
依据 DSH 当前 pending/sent 身份做一次定向对账，不能无条件批量删除全部 Bridge 数据。
